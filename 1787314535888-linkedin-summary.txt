Most fitness tracking apps are built with a backend API, a separate auth service, and a client that stitches it all together. This project collapses all of that into a single Next.js App Router codebase — and it's a great study in how far the modern stack has come.

**Performance Tracker** is a full-stack gym routine and workout session analyzer. You build routines, assign exercises to them, then log live sets — weight, reps, completion — all tied back to your profile. The data model is clean: profiles → routines → exercises (via a bridge table) → workout logs → session sets.

Here's what makes the architecture interesting:

🔁 **The Old Way vs The New Way**

| The Old Way | The New Way (This Project) |
|---|---|
| REST API routes for every mutation | Next.js Server Actions (`"use server"`) called directly from components |
| Separate auth microservice + JWT plumbing | Supabase SSR middleware — session refresh happens at the edge, automatically |
| Prisma or raw SQL with manual type mapping | Drizzle ORM — schema-first, fully type-safe, zero query builder magic |
| `useEffect` + fetch waterfalls on the client | React Server Components fetch data at render time, no client round-trips |
| Multiple `package.json`s for monorepo splits | Single pnpm workspace, clean and flat |

🛠️ **The Stack Breakdown:**
- **Next.js 16** (App Router) + **React 19** — the latest stable release of both
- **Drizzle ORM** — TypeScript-native schema definitions with inferred types straight from the table (`$inferSelect`, `$inferInsert`)
- **Supabase** — handles Postgres hosting AND auth, with the `@supabase/ssr` package wiring session cookies through Next.js middleware
- **Tailwind CSS v4** — the new Vite-native, zero-config PostCSS pipeline
- **TypeScript 5** throughout — every DB row type is auto-derived from the schema, no manual interface duplication

The part worth studying: the `middleware.ts` runs `supabase.auth.getUser()` on every request to silently refresh sessions without any client-side token management. That's auth that just works — no `useEffect`, no localStorage, no interceptors.

This is the pattern production apps should be moving toward in 2025.
